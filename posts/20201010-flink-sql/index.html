目标

达到这样的预期效果：

  1. 开发工作：编写 SQL 建表语句（输入表 Source、维度表、输出表 Sink），INSERT INTO 语句用于构建计算任务。或是 YAML 文件维护。No Java/Scala, No Maven, No JAR.
  2. 改造 ./bin/sql-client.sh 及其内核的 flink-sql-client 项目，用于方面提交上述 SQL 任务。

Flink SQL

DDL 相当于定义 POJO class。有Source，也有Sink，也有维度表。

DML 相当于 Transformation。

一直聚合，确实会有重复的 KEY，最后显示都是 GROUP BY KEY，取值都是 MAX(xxx)

The entire process can be completed using standard SQL syntax, without a line of Java or Scala code.

  1. 还有一个问题就是 kafka connector，消费的offset是怎么智能处理的，不会导致我重复消费之前的数据。
  2. 所有的建表操作都是在./sql-client.sh里完成的，怎么把它维护成一个任务呢？DDL、DML都做成脚本。一个任务该怎么组织。
  3. 如果只要写SQL，所以主要任务就是建一个Flink集群（on K8S），还有一套提交SQL任务的脚本。
  4. Time，State（比如分组统计，这些需要State的支持，重头开发，非常费劲的）
  5. 目前为止，对 time 的处理还不够深刻。processing time, event time。

SQL Client 是什么

Flink 任务的主流提交方式是 JAR 包。我想直接用 SQL 提交。

Flink’s Table & SQL API makes it possible to work with queries written in the SQL language, but these queries need to be embedded within a table program that is written in either Java or Scala. Moreover, these programs need to be packaged with a build tool before being submitted to a cluster. This more or less limits the usage of Flink to Java/Scala programmers.

必须打包成一个 JAR 包，这个有点费劲啊。

The SQL Client aims to provide an easy way of writing, debugging, and submitting table programs to a Flink cluster without a single line of Java or Scala code.

SQL Client 的方式就是不写Java/Scala，不用maven打包，只写SQL

Flink SQL 提交任务后，怎么追踪任务

The SQL Client does not track the status of the running Flink job after submission. The CLI process can be shutdown after the submission without affecting the detached query. Flink’s restart strategy takes care of the fault-tolerance. A query can be cancelled using Flink’s web interface, command-line, or REST API.

在 SQL Client 里提交的 INSERT INTO 会触发 Flink JOB，但是呢，Client 对其是失控的。只能使用 Web UI，命令行，REST API 来控制。

看着是，SQL Client 可以用来提交 SQL Flink 任务，但是呢，需要其他方式管理任务，创建任务与管理任务是两套。

调试 flink-sql-client 项目

怎么在 IDE 里调试 sql-client，我把一些依赖的包copy到源码目录，还是没法启动啊

(base) ➜ flink-sql-client git:(master) ✗ ./bin/sql-client.sh embedded

Error: Could not find or load main class org.apache.flink.table.client.SqlClient

下午讨论下。

  1. code review 监控系统 Flink 部分。新规则怎么快速构建呢，除了交易监控，还有优惠券等等的监控啊。
  2. 停机问题。停机一会，不影响吧，我们关注事件时间，而不是处理时间。重启后，之前的事件还是会处理的。
  3. 他们的思路是代码为主，配置为辅。我的思路是配置为主，参数、阈值作为维度表参与。一目了然。review SQL 比 review Java 快。
  4. 写 SQL 为何就费时费力呢？事件表、维度表，要统计的东西，很方便啊。也比较直观。Java 代码，不断重构抽象，都不直观了。
  5. 现在 Flink 集群是怎么部署的。
  6. 未来我们要容器化，容器化 Flink，应用容器化都要做。
  7. Flink SQL 不稳定，有多不稳定。最终都是翻译到 TableEnvironment 代码去的。
