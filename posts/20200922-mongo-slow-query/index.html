花了大量时间在 mongoDB 的客户端上。悲哀。

以下是 slow query log。

2020-09-20T01:47:05.216+0800 I COMMAND [conn734394782] command logs.mp.basket command: find { find: “mp.basket”, filter: { merId: “lx20200304155018111111”, _id: { $gt: ObjectId(‘5ed878a7fac9f829eb934ce4’) } }, sort: { _id: 1 } } planSummary: IXSCAN { id: 1 } keysExami ned:11903533 docsExamined:11903533 cursorExhausted:1 keyUpdates:0 writeConflicts:0 numYields:92997 nreturned:0 reslen:120 locks:{ Global: { acquireCount: { r: 185996 } }, Database: { acquireCount: { r: 92998 } }, Collection: { acquireCount: { r: 92998 } } } protocol:op query 12572ms

  1. [conn734394782] 看了下日志，这个连接有一直复用，初步判断是我的一个应用在进行查询。
  2. find { find: “mp.basket”, filter: { merId: “lx20200304155018111111”, _id: { $gt: ObjectId(‘5ed878a7fac9f829eb934ce4’) } }, sort: { _id: 1 } } 查询请求，应该就是捞数据。
  3. planSummary: IXSCAN { _id: 1 } 用了 _id 索引，发现没有建 merId 这个索引。
  4. keysExamined:11903533 docsExamined:11903533 因为 _id 索引，评估将要被scan的数据集差不多是整个collection。
  5. docsExamined The number of documents in the collection that MongoDB scanned in order to carry out the operation. https://docs.mongodb.com/manual/reference/database-profiler/
  6. numYields:92997 因为内存里没有当前操作需要的数据，所以让渡给其他操作早点完成任务，把内存腾出来给自己用 The number of times the operation yielded to allow other operations to complete. Typically, operations yield when they need access to data that MongoDB has not yet fully read into memory. This allows other operations that have data in memory to complete while MongoDB reads in data for the yielding operation. https://stackoverflow.com/questions/28762135/meaning-of-variables-in-mongodb-logs
  7. nreturned:0 结果返回 0 条 返回的条数并不是巨大量级的，所以加merId索引或许是有用的。
  8. reslen:120 返回结果的大小 When MongoDB writes query profile information to the log, the responseLength value is in a field named reslen. https://docs.mongodb.com/manual/reference/database-profiler/ The length in bytes of the operation’s result document. A large responseLength can affect performance.
  9. 12572ms 花了 12s 以上，妥妥慢查询

同样的查询请求，使用 merId 索引后，从耗时12s到0.002s。这样，112 个慢查询解决了。

db.mp.basket.find({ merId: "lx20200304155018111111", _id: { $gt: ObjectId('5ed878a7fac9f829eb934ce4') }}).sort({ _id: 1 })
// db.mp.basket.find({ merId: "lx20200304155018111111", _id: { $gt: ObjectId('5ed878a7fac9f829eb934ce4') }}).sort({ _id: 1 }).explain()

建索引

db.mp.basket.createIndex( { merId: 1 } )

参考：

  1. https://docs.mongodb.com/manual/reference/method/db.collection.find/#examples
  2. https://docs.mongodb.com/manual/indexes/index.html
  3. https://docs.mongodb.com/manual/reference/database-profiler/

这个聚合也很慢。不过，使用上索引后，时间下降到了 26s。

db.mp.basket.aggregate( [ { $group: { _id: "$merId", count: { $sum: 1 } } }, { $sort: { count: -1 } } ])
