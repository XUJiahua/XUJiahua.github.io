Go Memory Model

Happy Coding
 2020-10-15  416 words   2 minutes 
Contents
  • 参考

读这篇文章，让你写好并发代码，介绍了 Go 并发同步所用的工具。

一个变量在一个 goroutine 里修改了，在另一个 goroutine 能保证可见这个变量的修改（结果）。这是一个非常有用的，但对程序员透明的功能。

感觉是自己理解错了，并发同步还是得程序员来处理。只是Go内存模型提供一些工具，比如 channel、mutex，用于贯彻 happen before 策略。

The Go memory model specifies the conditions under which reads of a variable in one goroutine can be guaranteed to observe values produced by writes to the same variable in a different goroutine.

可见性问题，貌似与这个主题没啥关系啊？？？。现在操作系统架构，是多级缓存，多核心（多线程）的。线程模型，变量都会缓存于当前线程的缓存、寄存器中。也就是说，其他线程不可见该变量的改变，这会带来并发同步（变量）问题。

Java 里有 Volatile 关键字，就是为了解决这个问题，让变量存储于内存中，所有线程可见内存变量。（在介绍为何需要引入 Akka 模型中，有讲到这个背景。Akka 模型引入通过消息通信的方式，避免直面这个问题。）

“volatile” tells the compiler that the value of a variable must never be cached as its value may change outside of the scope of the program itself

这里 https://www.geeksforgeeks.org/volatile-keyword-in-java/ 有比较直白的描述。

Suppose that two threads are working on SharedObj. If two threads run on different processors each thread may have its own local copy of sharedVariable. If one thread modifies its value the change might not reflect in the original one in the main memory instantly. This depends on the write policy of cache. Now the other thread is not aware of the modified value which leads to data inconsistency.

并发修改（至少一个是write就会触发并发问题）数据，需要顺序化访问。

Programs that modify data being simultaneously accessed by multiple goroutines must serialize such access.

Golang 处理并发数据同步的方式有两种：

  1. 优先使用 channel 通信。
  2. 使用 mutex 锁。如果一个变量 a，不使用 mutex 保护下多 goroutine 修改，就会触发并发问题。

同步的关键，就是指令是顺序的。顺序的，确定的，就不会出错（出现不同的现象，只有一种结果）。

In all these examples, the solution is the same: use explicit synchronization.

package main

import (
	"fmt"
	"time"
)

var sharedVal = 1

func inc() {
	sharedVal ++
}

func main() {
	for i := 0; i < 2; i++ {
		go inc()
	}

	time.Sleep(time.Second)
	fmt.Println(sharedVal)
}

这种代码，使用race参数就可以检测出来了。

共享变量加锁。锁使得访问顺序确定了。

package main

import (
	"fmt"
	"sync"
	"time"
)

var sharedVal = 1
var l = &sync.RWMutex{}

func inc() {
	l.Lock()
	defer l.Unlock()
	sharedVal++
}

func main() {
	for i := 0; i < 2; i++ {
		go inc()
	}

	time.Sleep(time.Second)
	l.RLock()
	defer l.RUnlock()
	fmt.Println(sharedVal)
}

这句话什么意思：read r 被允许观察（可见） write w 更新的变量 v ，需要满足如下条件。

A read r of a variable v is allowed to observe a write w to v if both of the following hold:

（单个 goroutine 下）read r 可见最近一次 write w 更新的变量 v

a read r observes the value written by the most recent write w to v

多 goroutine 下，使用同步原语。

When multiple goroutines access a shared variable v, they must use synchronization events to establish happens-before conditions that ensure reads observe the desired writes.
