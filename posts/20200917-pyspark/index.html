Pyspark的执行原理，较scala开发的不同？

其执行原理是计算任务在每个节点安装的Python或R的环境中执行，结果通过管道输出给Spark Worker，因此效率要比Scala与Java低，

作为统一的入口，spark-submit 兼容了很多启动方式、资源调度工具。

如果是 pyspark 启动的（SparkContext._ensure_initialized()），通过 spark-submit 这个命令，启动一个子进程，也就是 PythonGatewayServer 。两者通过 TCP 通信。

    // If we're running a python app, set the main class to our specific python runner
    if (args.isPython && deployMode == CLIENT) {
      if (args.primaryResource == PYSPARK_SHELL) {
        args.mainClass = "org.apache.spark.api.python.PythonGatewayServer"
      } else {
        // If a python file is provided, add it to the child arguments and list of files to deploy.
        // Usage: PythonAppRunner <main python file> <extra python files> [app arguments]
        args.mainClass = "org.apache.spark.deploy.PythonRunner"
        args.childArgs = ArrayBuffer(localPrimaryResource, localPyFiles) ++ args.childArgs
      }
    }

spark-submit 会创建一个子进程 SparkApplication 内部执行具体程序。

貌似不是子进程，只是直接执行一个class而已。

除了 JavaRDD，还有 PythonRDD，底层都是 RDD。这种与语言绑定的RDD，就会触发生成该语言的子进程。

比较关心 Exectuor 与子进程 Python Worker 之间的交互。
