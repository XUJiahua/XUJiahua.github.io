icmptunnel 中有用到 TUN 虚拟（Virtual）网络设备，本文整理下。

Linux 中有别于物理网络设备的，背后没有真实物理网卡，完成通过软件虚拟化的就是虚拟网络设备了。虚拟网络设备的应用场景很多，比如 VirtualBox 虚拟机内的网卡是虚拟出来的，VPN（Virtual private networks）网络是基于虚拟网络设备的。

先重点讲下 TUN/TAP 这两种虚拟网络设备，主要用途就是建立隧道网络。

tunnel 隧道，联通两块陆地。

Linux L3隧道底层实现原理都基于tun设备。现在的Linux内核原生支持5种隧道协议，它们的底层实现都采用tun设备。我们熟知的各种VPN软件，其底层实现都离不开这5种隧道协议。其他隧道实现方式与ipip隧道的大同小异。

TUN/TAP

工作原理

https://blog.csdn.net/bailyzheng/article/details/18770121

Virtual NIC：同 Real VIC 一样，是内核资源，只是没有物理链路，向上的抽象是一样的，同样经过 TCP/IP 协议栈。

数据处理进程：通过系统调用创建了 TUN/TAP 虚拟网卡（ifconfig 可见类似 tun0/tap0 的网卡名称），使用 ip/ifconfig 配置 IP address 等。对数据处理进程来说，与 VIrtual NIC 的通信跟读写文件一样简单，因为中间有字符驱动。

使用 tun/tap 驱动的进程：通过 IP 访问 TUN/TAP 虚拟网卡，即，实现了与数据处理进程之间的通信。

Real NIC：为了达到数据转发的目的，数据处理进程通过 Socket 通信与其他网络地址通信，当然，这会经过物理网卡，也就是会经过 Real NIC。

其工作原理，大体也是如 Shadowsocks 这类软件的工作思路。

TUN 与 TAP 的区别

https://en.wikipedia.org/wiki/TUN/TAP

封包的层次不一样，TUN 是网络层的，封装 IP 包，而 TAP 是链接层的。

如何使用 tun

In order to use the driver a program has to open /dev/net/tun and issue a corresponding ioctl() to register a network device with the kernel. A network device will appear as tunXX or tapXX, depending on the options chosen. When the program closes the file descriptor, the network device and all corresponding routes will disappear.

Depending on the type of device chosen the userspace program has to read/write IP packets (with tun) or ethernet frames (with tap). Which one is being used depends on the flags given with the ioctl().

https://www.kernel.org/doc/Documentation/networking/tuntap.txt
