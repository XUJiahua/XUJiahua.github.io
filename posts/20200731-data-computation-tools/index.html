记得入门数据科学，用的是pandas，结构化数据用DataFrame承载很方便，DateFrame数据清洗完，与Scikit-Learn衔接得很好，就可以进入机器学习环节了。

后来的Spark也有了DataFrame，当然Spark SQL更加方便了，SQL的表达简洁有力，大数据上做BI报表很方便。

本文梳理下这些好用的数据计算工具。

评估一个数据计算工具，主要是考察这些方面的能力：

  1. 分布式计算的能力。Scale Out 横向扩展的能力。
  2. 数据是懒加载的，还是直接读入内存的。

Pandas系列

Pandas

https://pandas.pydata.org/

  1. 先驱者。也有好多学习资料。
  2. 并行能力不行。One can only use one core at a time when doing computation. 这里例子，https://stackoverflow.com/questions/45545110/how-do-you-parallelize-apply-on-pandas-dataframes-making-use-of-all-cores-on-o 以前我也困扰过。因为这个问题，各种并行计算的扩展也出来了。
  3. Load大数据集也很慢。即使没有计算，也要把所有数据存储到内存中。
  4. 仅供学习使用。

Dask – 多核多机上扩展

Dask is a flexible library for parallel computing in Python that makes scaling out your workflow smooth and simple.

  1. Dask的原理是master/worker这种结构，使用TCP通信，所以可以支持多机通信。https://www.youtube.com/watch?v=TQM9zIBzNBo&list=UUj9eavqmvwaCyKhIlu2GaoA&index=5
  2. 与Pandas相比，需要多调用一句.compute() 。可能会造成困扰。

信息来源：

  1. Dask Introduction: https://www.youtube.com/channel/UCj9eavqmvwaCyKhIlu2GaoA
  2. https://docs.dask.org/en/latest/why.html

RAPIDS – GPU上扩展

主要是这两个库cuDF，Dask-cuDF。

  1. cuDF is a Python GPU DataFrame library (built on the Apache Arrow columnar memory format) for loading, joining, aggregating, filtering, and otherwise manipulating data. If your workflow is fast enough on a single GPU or your data comfortably fits in memory on a single GPU, you would want to use cuDF. 单GPU。

  2. Dask is a flexible library for parallel computing in Python that makes scaling out your workflow smooth and simple. 是上文所说的Dask并行工具。

  3. Dask-cuDF is a library that provides a partitioned, GPU-backed dataframe, using Dask. If you want to distribute your workflow across multiple GPUs, have more data than you can fit in memory on a single GPU, or want to analyze data spread across many files at once, you would want to use Dask-cuDF. 多GPU。

  4. cuDF is a single-GPU library. For Multi-GPU cuDF solutions we use Dask and the dask-cudf package, which is able to scale cuDF across multiple GPUs on a single machine, or multiple GPUs across many machines in a cluster.

  5. Dask DataFrame was originally designed to scale Pandas, orchestrating many Pandas DataFrames spread across many CPUs into a cohesive parallel DataFrame. Because cuDF currently implements only a subset of Pandas’s API, not all Dask DataFrame operations work with cuDF.

信息来源：

  1. https://rapidsai.github.io/projects/cudf/en/0.12.0/10min.html
  2. https://rapidsai.github.io/projects/cudf/en/0.12.0/dask-cudf.html

blazingsql (SQL engine based on GPU)

https://docs.blazingdb.com/docs

  1. SQL引擎，类比SparkSQL。号称比同等量级的Spark运行速度快。
  2. 依赖Apache Arrow，列式内存存储格式（非持久化存储格式）（与Parquet数据格式有点渊源）
  3. 与Spark比起来，blazingsql利用GPU来加速计算
  4. GPU DataFrames (GDFs)
  5. 支持的文件系统：HDFS、S3、GoogleCloudStorage | 竟然没有本地文件系统？
  6. 支持的数据格式：文本（csv）/ JSON / Parquet（列式存储）

Modin

又一个类似Dask的产品。还在早期阶段。

  1. Modin uses Ray or Dask to provide an effortless way to speed up your pandas notebooks, scripts, and libraries.

信息来源：

  1. https://modin.readthedocs.io/en/latest/

Spark

Hadoop生态中MapReduce计算框架的继承者，内存计算，为分布式计算而生。

其最好用的就是SQL的能力了，清洗数据好方便。

Dask (Pandas) vs. Spark

考虑到Pandas并行计算的薄弱，可以先放一边。考虑到GPU不是每家公司会使用到，RAPIDS稍微放放。

主要是Dask与Spark之间的较量。Dask官方有两者的比较：https://docs.dask.org/en/latest/spark.html。

节选一些我觉得重要的比较。

  1. 以Dask为主的Pandas on XXX，扩展Pandas并行能力的目的，就是尽可能代码复用，在 10KB 和 10TB 的数据上使用相同的 Pandas 脚本。不然就得在Spark上重新开发。
  2. 如果NumPy/Pandas/Scikit-learn/Jupyter技术栈，用Dask。
  3. 两者都是Master/Slave的模式。
  4. 单机到集群的扩展都很方便。
  5. 想用SQL，做数据清洗更方便。用Spark。
  6. Spark is more focused on traditional business intelligence operations like SQL and lightweight machine learning. lightweight machine learning指的是Mllib。Spark提供的JDBC接口，可以直接被BI Dashboard使用。
  7. Dask is applied more generally both to business intelligence applications, as well as a number of scientific and custom situations.
  8. 更丰富的机器学习能力，比如Scikit-learn/XGBoost，用Dask。深度学习框架不在此列。

未整理

计算有两种模式：

  1. Eager 马上计算，所见即所得。缺点也很明显，因为要马上加载数据，内存不够，大数据无法加载完全，也就不适合大数据计算。

  2. Lazy 懒计算，按需计算。除了不直观，都是优点。适合大数据计算。还适合做优化。DAG，不仅是Spark，TensorFlow也是这个风格。方便scale，当然需要RDD这种基础的支持。

数据探索

数据探索流程有套路，而现在还是得写重复的Python代码或是SQL代码来分析。可以把数据探索的知识做成软件。
