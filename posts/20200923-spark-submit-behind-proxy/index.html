目标

本地电脑通过代理连入大数据集群的网络，本地开发，并 spark-submit 提交任务到大数据集群。

创建代理

$ ssh -ND 8080 webapp@ip_of_spark_cluster

准备工作

下载集群上的 spark 版本。打包下载即可。

CDH 下载 YARN 的 CONF 文件。以及将当前的hadoop用户指定为 spark ，不然当前用户没有权限。

export HADOOP_CONF_DIR=~/Downloads/yarn-conf/
export HADOOP_USER_NAME=spark

YARN 有两种模式。

There are two deploy modes that can be used to launch Spark applications on YARN. In cluster mode, the Spark driver runs inside an application master process which is managed by YARN on the cluster, and the client can go away after initiating the application. In client mode, the driver runs in the client process, and the application master is only used for requesting resources from YARN.

driver 主动发起的通信，因为有代理网络，是没问题的。

如果其他进程主动发起的通信到 driver 呢，就找不着了！network latency between the drivers and the executors

看图，driver 会主动连接 executor，executor 也会主动连接 driver。

大致架构如图。driver 与 executor 之间是互相通信的。

Responsibility of EXECUTOR

  1. To run an individual Task and return the result to the Driver.
  2. It can cache (persist) the data in the Worker node.

https://blog.knoldus.com/understanding-the-working-of-spark-driver-and-executor/

client 模式

https://stackoverflow.com/a/51763002

driver 进程在本地。

cluster manager 就是 YARN，Spark 只知道通过 YARN 可以申请到 executor process 资源。然后 spark driver 与 spark executor 之间是会互相通信的。

spark driver 必须监听一个端口，因为 spark executor 会与之通信。所以 spark driver 所在节点必须是 worker 节点网络可达的。现在只有 driver 通过 proxy 访问 executor，而 executor 无法访问 driver，因为网络不可达。

Spark is agnostic to the underlying cluster manager. As long as it can acquire executor processes, and these communicate with each other, it is relatively easy to run it even on a cluster manager that also supports other applications (e.g. Mesos/YARN).

The driver program must listen for and accept incoming connections from its executors throughout its lifetime (e.g., see spark.driver.port in the network config section). As such, the driver program must be network addressable from the worker nodes.

Because the driver schedules tasks on the cluster, it should be run close to the worker nodes, preferably on the same local area network. If you’d like to send requests to the cluster remotely, it’s better to open an RPC to the driver and have it submit operations from nearby than to run a driver far away from the worker nodes.

https://www.ikbigdataanalytics.com/2018/09/spark-components-communication.html

$ proxychains4 ./bin/spark-submit \
  --class org.apache.spark.examples.SparkPi \
  --master yarn \
  --deploy-mode client \
  examples/jars/spark-examples_2.11-2.4.0-cdh6.3.2.jar \
  1000

结论

因为本地与集群不是在一个网络（互相可达）里，client 模式就不能用了，因为 executor process 无法与 driver process 通信。client 模式的好处是本地能看到一些结果。适合 spark-shell 这种需要交互的场景。

只能使用 cluster 模式。本地通过代理 spark-submit 提交任务到集群中，driver process 在集群内创建，与 executor process 通信问题就不用担心。

Python cluster 模式在本地没有调试通过，有点难。

提交 jar 包，以及 cluster 模式的方式提交，比较合适使用代理的方式。

鉴于目前是以 Python 开发 Spark 应用为主，可先用 Python 开发，然后通过代理同步到集群内，在集群里执行任务更合适目前的状况。
