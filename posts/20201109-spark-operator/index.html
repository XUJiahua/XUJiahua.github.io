尝试Spark over K8S，在阿里云集群上没有跑成功，需要重新搞下镜像，烦人的防火墙。思路仍然是 Operator，还有用 helm 封装！值得研究。

https://github.com/GoogleCloudPlatform/spark-on-k8s-operator

镜像被GFW了

https://www.iguazio.com/blog/spark-over-kubernetes/ 这篇文章里，仍然使用的是 v1beta1，最新版本是 v1beta2。

而且 v1beta2 支持的 Spark 也变了，示例中的 yaml 文件也得更新了。

(base) ➜  igz_sparkk8s git:(master) ✗ kubectl get pods -n spark-operator
NAME                                        READY   STATUS             RESTARTS   AGE
sparkoperator-1604903084-7fc449bcfb-cbb8n   0/1     ImagePullBackOff   0          22m

Spark-operator 镜像没拉下来？错误日志，被强了。。。

Failed to pull image “gcr.io/spark-operator/spark-operator:v1beta2-1.2.0-3.0.0”: rpc error: code = Unknown desc = Error response from daemon: Get https://gcr.io/v2/: net/http: request canceled while waiting for connection (Client.Timeout exceeded while awaiting headers)

helm 非常有误导性：

(base) ➜  igz_sparkk8s git:(master) ✗ helm list -A
NAME                     	NAMESPACE     	REVISION	UPDATED                                	STATUS  	CHART                          	APP VERSION
sparkoperator-1604903084 	spark-operator	1       	2020-11-09 14:24:45.981017 +0800 CST   	deployed	sparkoperator-0.8.5            	v1beta2-1.2.0-3.0.0

实际上参考官方示例就行了。 https://github.com/GoogleCloudPlatform/spark-on-k8s-operator/blob/master/docs/quick-start-guide.md

知识点：

  1. Helm YAML的封装
  2. Operator 自定义资源和 Controller 的封装
  3. Spark 使用 Kubernetes 调度的思路
