  3. 还有特别的费劲的是，非得写成多个任务，因为有些任务需要连hadoop环境，需要认证，这个azkaban一些特殊任务类型是自动支持的。???

通过 Socks5 代理伪装本地环境为集群环境

目前两种开发模式：

  1. Zeppelin Notebook 上写好并调试好主要逻辑的PySpark/SQL脚本，然后将脚本贴入一个脚手架pyspark程序中。问题是测试只测到核心逻辑。
  2. 本地准备一个Spark环境，准备些数据，写完pyspark可以直接调试。问题是本地环境与生产环境有差异，数据准备也是不容易。

以上测试都不够充分，直到打包上传到Azkaban，在Azkaban上执行，才会知道脚本是否真正无错误。

理想的开发模式，是本地开发环境直接连入集群，开发调试，能测到全量数据、也能测到整块代码。本地开发环境，可以使用自己喜欢的IDE。

ssh -ND 开个代理服务器，程序里设置proxy代理，请求就会直接进入服务器了。不需要本地有内网IP。

Git 持续集成

目前的开发部署流程，本地开发完成，运行打包脚本，上传Azkaban。

这块完全可以通过持续集成来做到。开发只要做到代码Git提交，发PR即可。不手动打包、不手动上传交付物。
