Ray 简介

Python 的数据科学生态软件 numpy，scipy，pandas，scikit-learn 都是单机的，pandas的计算更是只能使用一个CPU core，跟不上多核多机分布式计算的大形式了。

Ray 就是在这个背景下产生的。Ray Core 是一个用于开发分布式应用的框架。基于Ray Core，Ray 生态主要是数据科学相关，比如分布式机器学习训练、可伸缩的机器学习超参数调优。

On top of Ray Core are several libraries for solving problems in machine learning:

  • Tune: Scalable Hyperparameter Tuning
  • RLlib: Scalable Reinforcement Learning
  • RaySGD: Distributed Training Wrappers
  • Ray Serve: Scalable and Programmable Serving

Ray also has a number of other community contributed libraries:

  • Pandas on Ray
  • Distributed Scikit-learn / Joblib
  • Distributed multiprocessing.Pool

其中 Pandas on Ray 的思路，兼容 Pandas API，照顾老用户使用习惯，底层用 Ray 重写了。所以 Pandas on Ray 不是 Pandas。类似的项目有 Dask。

对于计算密集型任务来说，利用多核才能提高性能。多线程的手段只会降低总体性能，因为CPU还花时间在线程调度上了。

process

多进程是最简单粗暴的。

GIL

全局解释器锁（Global Interpreter Lock，缩写GIL）造成的结果，单进程无法利用多核。除非使用多进程。

  • CPython的线程是操作系统的原生线程。在Linux上为pthread，在Windows上为Win thread，完全由操作系统调度线程的执行。一个Python解释器进程内有一个主线程，以及多个用户程序的执行线程。即便使用多核心CPU平台，由于GIL的存在，也将禁止多线程的并行执行。[2]

Go单进程利用多核。

Python单进程只能利用单核，所以需要显式地多进程。

multiprocessing.Pool

为了充分利用多核资源，Python引入multiprocessing多进程包。通过多进程的方式避免GIL带来的限制，每个进程。

资源与调度

多机多核。

参考：Ray Dashboard

资源有内存（还能细分）、CPU。

分配给worker的资源不能超过资源的总数，比如节点有8个CPU，那就只有8个标记为remote的方法并行执行。

一个remote分配的最小资源是一个CPU。如果这个remote没有充分利用CPU（只占25%），比如仅仅是网络请求，网络等待的时间比较多，CPU是浪费的。

ray.timeline('timeline.json')

https://docs.ray.io/en/latest/package-ref.html#ray.timeline

保存的timeline.json文件使用 chrome://tracing 打开。多核利用起来了。

缩放看细节。driver大部分时间都在ray.wait，等待时间大概是一次task的执行时间。worker都是在执行task，空闲率不多（空白处）。

再次缩放，ray.wait等待一些task完成，ray.get获取结果后，submit_task提交任务。
