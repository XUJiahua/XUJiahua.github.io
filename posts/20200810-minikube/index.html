体验 Kubernetes

准备工作

一台 Linux 虚拟机（vagrant 启动虚拟机）。需要满足条件 https://kubernetes.io/docs/setup/production-environment/tools/kubeadm/install-kubeadm/#before-you-begin。VM本身不需要虚拟化。

使用 minikube 安装集群。

minikube 支持各种driver，我们会使用None https://minikube.sigs.k8s.io/docs/drivers/none/ 所以不会用到虚拟化。

使用 yaml 文件，直接使用命令不利于git保存。使用 apply。

传统部署方式遇到的问题：

  1. Node 上多应用，可能端口冲突。
  2. Node 上多应用，有资源竞争问题，合理分配困难。

使用 K8S

  1. 资源合理分配由系统处理。
  2. 端口不怕冲突，K8S集群内的内部网络，每个容器化应用都有独立IP、独占整个端口范围区间。

Kubernetes 逻辑上架构还是主从架构。Control Plane + Nodes 的组合。

Control Plane 包含如下组件：

  1. etcd KV数据库，Kubernetes的存储核心。
  2. apiServer。操作入口，一般是kubectl工具连入apiServer，运维使用kubectl工具。
  3. Controller？比如 Replication Controller。类比恒温器。
  4. coreDNS

Node 包含如下组件：

  1. kubelet 与apiServer 通信？
  2. kubeproxy 网络
  3. container runtime 比如常用的 Docker

这些组件呢，都是以容器的形式安装的。

install kubectl

需科学上网，不用直接安装。

kubernetes-cli-1.18.6.mojave.bottle.tar.gz

brew install kubectl

需科学上网

brew install minikube

Kubernetes的组件也是以容器的方式安装的。这些组件的下载地址k8s.gcr.io境内无法访问，需要使用 registry.cn-hangzhou.aliyuncs.com/google_containers。

minikube start --image-repository='registry.cn-hangzhou.aliyuncs.com/google_containers'

kubectl create deployment hello-minikube --image=registry.cn-hangzhou.aliyuncs.com/google_containers/echoserver:1.4
kubectl expose deployment hello-minikube --type=NodePort --port=8080

kubectl expose deployment hello-minikube --type=LoadBalancer --port=8080

node

pod K8S中的最小执行单元，可含有多个容器（主容器+sidecar容器，共享相同的网络栈）。

deployment 一般不会直接创建 Pod，而是通过创建Pod的deployment，间接创建Pod。这块涉及到资源调度，K8S会处理，运维不用关心。

service Pod的网络是K8S内的虚拟网络。每个Pod有分配一个虚拟网络的IP。service 将流量带入Pods。

怎么调试 Pod呢，查看容器内 接口的返回？直接进入容器，这个不错！

kubectl exec -ti $POD_NAME -- bash

kubectl apply -f yaml/echoserver-deployment.yaml

kubectl expose deployment echoserver-deployment --type=NodePort --port=7893

发现负载均衡不够平衡啊，一直在一台机器上？
minikube service echoserver-deployment
